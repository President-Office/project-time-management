## 使用原则

1. 副业项目用于每周时间分配和优先级排序。
2. 本职工作只记录跟进点、阻塞和下一步，不参与副业排序。
3. `Enterprise Service` 是副业中的对外客户技术赋能业务，不属于 `official-work`。
4. `AI 软件工厂 / youlidao.ai` 已放弃并归档；正式工作的 SnapOne 历史记录仍保存在 `official-work`，两者不混用。
5. 能力中心/平台型 BU 可以进入同一 dashboard，但不和具体业务的 Q1 优先级混算。
6. 重要紧急四象限用于每周判断先处理哪些项目；每周先核对明确的当前承诺，再单独看主业与副业事项。
7. Hold、暂停和归档项目保留历史资料，但不默认占用当前时间；恢复前重新确认容量、范围与价值。
8. 项目优先级不等于每天可用的精力或容量；安排每周投入时要为突发事项、切换成本和恢复留余量，计划被打断后及时重排，而不是把所有未完成项都视为必须补齐。
9. 每周先依据[真实容量与时间约束](weekly-capacity.md)确认可承诺时间，再决定项目投入；没有观察数据前，不把未安排时段、深夜或周末默认视为可用容量。

## 信息治理

1. GitHub Organization 是资产归属的真相源。
2. 各 Organization 的 `requirements` 仓库是业务需求的真相源。
3. 本仓库文档是项目优先级的真相源。
4. GitHub Issues 是当前可执行任务的真相源。
